# 공용 운영 규칙 (Codex · Claude 공통)

두 에이전트(Codex, Claude) 중 어느 쪽이 작업하든 이 파일과 `ops/queue/ledger.json`을 따른다.
토큰이 떨어지면 다른 쪽이 그대로 이어받는다. 작업을 시작할 때마다 두 파일을 먼저 읽는다.

- 한 채널 글을 다른 채널에 대신 올리지 않는다.

## 사실 확인과 상태값
- 실제로 게시된 글은 vidIQ `social_post_list`를 기준으로 판단한다. 어느 에이전트가 올렸든 같은 목록에 나온다.
- 승인과 검증 상태는 `ops/queue/ledger.json`에 기록한다.
- 두 기록이 서로 다르면 vidIQ 쪽을 믿고 ledger를 고친다.

## 항목 상태 흐름
`draft` → `review`(사용자에게 최종본을 보여줌) → `approved`(사용자가 그 정확한 버전을 승인) → `in_progress` → `published`
- `hold`: 검증 보류. 사유를 반드시 함께 기록한다.
- 승인은 버전 해시 단위로 받는다. 이미지나 본문이 한 글자라도 바뀌면 새 버전이므로 다시 승인받는다.
- 사용자가 보지 않은 버전은 절대 승인 처리하지 않는다.

## 게시 조건 (모두 충족해야 게시)
1. 정확한 버전이 승인됨
2. 핵심 사실과 시의성을 다시 확인함
3. 사진·방송 화면을 쓸 근거(라이선스, 출처)를 확인함
4. 파일 해시가 일치함
5. 같은 채널의 직전 실제 완료 게시로부터 4시간 이상 지남. vidIQ `social_post_list`의 `completedAt`으로 확인한다.
6. ledger에 해당 항목이 `in_progress`나 `published`로 이미 잡혀 있지 않음. 다른 에이전트가 처리 중일 수 있다.

- 게시를 시작하기 전에 ledger에 `in_progress`, 담당 에이전트, 시각을 먼저 기록한다.
- 게시가 끝나면 링크, 버전, 실제 게시 시각, 음악 적용 여부를 기록한다.
- 한 번에 1건만 게시한다. 보류나 실패 뒤 밀린 글을 한꺼번에 올리지 않는다.
- 이미 게시된 항목은 재게시하지 않는다. 예: L003 ece6b2a125f6 → https://www.instagram.com/p/DftRS0GDTne/
- 대기열이 비어 있으면 아무것도 새로 만들어 게시하지 않고 종료한다.
- 캐러셀 음악은 현재 도구가 지원하지 않는다. 음악을 적용했다고 기록하거나 말하지 않는다.

## 편집 기준 (사실 확인)
- 숫자, 날짜, 발언, 원인, 인물 관계 하나하나를 실제로 열람한 원자료(URL, 날짜, 해당 문장이나 타임스탬프)에 연결해 `ops/evidence/<ID>.md`에 기록한다.
- 기사, 스크린샷, 다른 채널은 원자료를 찾는 단서일 뿐 확정 근거가 아니다. 같은 원문을 재인용한 기사가 여러 개여도 한 건으로 센다.
- 확인된 사실, 당사자 주장, 추정, 루머를 구분해서 쓴다. 제목도 검증 대상이다.
- 확인되지 않은 인과관계, 열애, 범죄, 감정, 출시 확정, 흥행·수익은 쓰지 않는다.
- 사진은 실제 인물, 장면, 시기가 맞는지 확인하고, 자료사진·상상도·AI 재현이면 그렇게 표시한다.
- 공개 캡션에는 출처 URL을 넣지 않는다. 다만 사진 크레딧과 내부 근거 기록은 반드시 남긴다.
- 근거가 부족하면 해당 문장을 고치거나 빼고, 그래도 안 되면 `hold`로 둔다.

## 역할 분담 (번갈아 쓰기)
- 주 담당:
  - Codex: 인스타 캐러셀 수집·제작 → vidIQ 초안(publishAt 필수)
  - Claude: 인스타 게시(사용자 컨펌 후), YouTube 쇼츠, 블로그 자동화
- 공유 채널: vidIQ(게시·초안·예약 목록)와 이 저장소의 ops/ 폴더. 작업이 끝나면 각자 ledger에 기록한다.
- 제작과 게시 중 어느 쪽이든 아무 에이전트나 맡을 수 있다. 같은 규칙이므로 이어받으면 된다.
- 권장 분담: Codex는 제작 → `review`. 사용자 승인 → `approved`. Claude가 게시.
- 이어받는 쪽은 vidIQ `social_post_list`와 ledger를 대조한 다음 시작한다.
