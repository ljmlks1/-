# ig-publish: Claude는 게시만 담당한다

제작(자료 수집, 사실 확인, 캐러셀 만들기)은 Codex가 한다. Claude는 아래 단계로 게시만 한다.
공유 대기열은 vidIQ의 날짜가 지정된 초안(`publishAt`이 있는 draft)이다.
날짜가 없는 초안은 목록에 나오지 않는다.

## 계정
- issue.ap → `29314331491559156` (과학·상식·뉴스)
- legendhumormeme → `29028458450154197` (유머·예능)

## 1. 대기열 보기
1. `vidiq_social_post_list`를 호출한다. 조건: `statuses: ["draft"]`, `from`은 지금부터 30일 전, `to`는 지금부터 60일 후.
2. 같은 `postId`는 한 번만 센다.
3. 각 초안을 `vidiq_social_post_draft_get`으로 읽는다. 캡션 전문, 이미지 순서, 대상 계정, `revision`을 확인한다.
4. 사용자에게 번호를 붙여서 보여준다. 항목마다 채널, 캡션 전문, 이미지 장수, 각 장 미리보기, 예정 시각을 보여준다.
5. 아래 확인 결과를 함께 표시한다.
   - 채널과 내용이 맞는지 (유머 글이 issue.ap에 잡혀 있지 않은지)
   - 같은 채널에 이미 올라간 글과 중복되지 않는지 (최근 completed 목록과 비교)
   - 캡션에 출처 URL이 들어가 있지 않은지
   - 해시태그가 5개 이하인지
   - 사진 크레딧이 이미지에 표시돼 있는지
   - 직전 게시 시각, 4시간 간격 충족 여부

## 2. 컨펌을 받은 경우에만 게시
- 사용자가 그 번호를 직접 승인한 경우에만 게시한다. 예: "1번 OK", "1, 3 올려".
- 질문하거나 수정을 요청한 것은 승인이 아니다.
- 게시 직전에 `vidiq_social_account_list`로 username과 `canPublish: true`를 확인한다.
- `draft_get`을 다시 호출해서 `revision`이 보여준 것과 같은지 확인한다. 다르면 바뀐 부분을 다시 보여주고 다시 컨펌을 받는다.
- 4시간 간격을 지켜야 할 때 처리 방법:
  - 바로 올릴 수 있으면 `publishAt`을 지운 뒤 게시한다.
  - 아니면 `publishAt`을 직전 게시 + 4시간으로 바꾼다. 이 경우 사용자에게 예약 시각을 알리고 그 시각으로 컨펌을 받는다. 예약된 글은 취소할 수 없다.
- 게시는 `vidiq_social_post_publish(postId, revision)`로 한다. 한 번에 1건씩 처리한다.
- 결과는 `vidiq_social_post_status`로 확인한다. completed와 링크를 확인한 뒤에만 "완료"라고 말한다.
- 음악은 적용되지 않는다. 적용했다고 말하지 않는다.

## 3. 하지 않는 것
- 제작, 내용 수정, 사실 판단을 대신하지 않는다. 문제를 발견하면 보고만 하고 Codex 쪽 수정을 권한다.
- 사용자가 보지 않은 버전은 게시하지 않는다. 밀린 글을 한꺼번에 게시하지 않는다.
- 이미 completed인 글은 재게시하지 않는다.
